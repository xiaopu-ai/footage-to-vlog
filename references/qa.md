# 渲染、检查和交付

规则级别见 `rules.md`：A / B 级必须过，C 级的例外要写理由。

## 渲前清单（整片渲染前逐条过）

- [ ] `timeline.py` lint 零错误，警告逐条看过（C 级例外写进 `note`）。
- [ ] `coverage.py`：素材用得够、没有源区间重叠；复用多的有理由。
- [ ] 每镜首、中、尾抽帧看过：
  - 没有商标、车牌 / 船号、第三方品牌、二维码、电话、地图；
  - 画面和说的话对得上；
  - 字卡不挡脸。
- [ ] 采访说话中全部是硬切。
- [ ] 毛笔字清楚；居中元素量过像素（误差 ≤ 2 px）；同组卡片行数和尺寸一致。
- [ ] 字幕没拆词。
- [ ] 合规删句后，前后句都说完整了。
- [ ] 参数逐条对过官方参数表；口号和 Logo 用的是官方写法 / 官方文件；落版 Logo 和 PLAN 的品牌层级一致。
- [ ] 节奏预演用户已经通过（`state.py status` 里 rhythm 是「通过」，而且没有失效）。

## 渲染：只用 `render.py`

```bash
python3 $SK/scripts/render.py <proj> --preview 15 --allow-draft   # 节奏预演：开场 15 秒、半分辨率，可以用 draft 片段
python3 $SK/scripts/make_clips.py <proj>                          # 整片前把片段切成 final
python3 $SK/scripts/render.py <proj> --name <片名>-v1             # 整片
```

`render.py` 不只调一次 Remotion，它按顺序做这几件事：

1. 检查片段：整片必须全部是 final。
2. Remotion **静音**渲画面，用 PNG 帧，输出 yuv420p、BT.709。
3. 核对帧数，多出来的帧裁掉。
4. `mix.py` 按 timeline 混出**规范混音**（和模板 `FilmAudio.tsx` 同一套音量算法，只是不带 Remotion 自己的取整）。
5. 先限幅、再两遍响度标准化，到 −14 LUFS / −1.5 dBTP。
6. 用 ffmpeg 封装：视频流不重编码，补齐 BT.709 色彩标签；音频编码成 AAC。
7. 整片另出无声版；有人声的再出纯人声版。
8. 写渲染清单 `work/render/<名>.json`，记录命令、帧数、各文件 sha256、响度。

为什么不直接用 Remotion 带声音的输出：两次实测都发现直出的音轨比画面晚约 40 ms，色彩是全范围 BT.601，而且多 2 帧。

## 渲后检查：`qa.py` 一条命令

```bash
python3 $SK/scripts/qa.py <proj> out/<片名>-v1.mp4 --kind film
```

结果写进 `work/qa/<名>.QA.json`，并打印汇总表。**任何一项 fail，退出码就非零**，不能只看最后一行。

| 检查 | 通过标准 | 覆盖范围（报告里照实写） |
|---|---|---|
| 帧数、时长 | 等于 timeline 的时长或预演范围 | 全片 |
| 色彩 | yuv420p、tv 范围，BT.709 的 primaries / transfer / matrix 三项齐全 | 容器和码流标签 |
| 音画对齐 | 成片音轨和规范混音的时移 ≤ 5 ms | 降采样互相关，报告里写测量精度和相关系数 |
| 响度 | −14 LUFS ±0.5，真峰值 ≤ −1.5 dBTP | 全片 |
| 卡点 | 设计切点和画面实际切点一致；卡点类风格 drop 段（没写 drop 段就是全片）的硬切落在强重音 ±2 帧内：燃剪 ≥ 60% 才算通过，低于 75% 告警。画面目标帧 = 重音帧 − lead_frames | 只测 cut / punch / whip 这类硬切换；fade / wipe / sweep / dip 是过程转场，单列 |
| 意外黑场 | timeline 声明的暗场以外没有黑场 | 声明的暗场：dip 转场、黑场镜头、深底落版 |
| 抖动 | 没有「来回跳」 | 只查 A-B-A 型来回跳，不代表所有卡顿都排除了 |
| 二维码 | 解不出内容 | 2 fps 均匀扫 + 每镜首、中、尾三帧，短镜不会漏；报告写明扫了哪些帧 |
| 素材覆盖 | 没有源区间重叠 | 来自 `coverage.py` |

### 卡点的正负号（统一定义）

```
lead_frames = (音频起音时间 − 画面切点时间) × fps
lead_frames > 0 表示画面先到
```

- 设计上，画面领先 0–2 帧（小节头的刀放在当帧或前 1 帧）。
- 「领先 0–2 帧」是有意的提前量，「±1.5 帧」是相对这个提前量的误差，两条不要混在一起判。
- 卡点不达标时，**不要一上来就把 edit.json 整体平移**。先看音画对齐（封装延迟）、重音检测对不对、匹配到的是不是旁边另一个起音，排除这些以后再动剪辑。

### 怎么汇报

- 只说跑过的检查，并带上覆盖范围。
- C 级规则的例外、没跑的项、要人工看的项单独列。
- 「agent 看过静帧」「数值检查通过」「用户批准」分开说（见 `rules.md` 末节）。

## 交付物

- `out/<片名>-v<N>.mp4`：成片，1920×1080、30 fps、H.264 yuv420p BT.709、AAC、−14 LUFS。
- 无声版（纯音乐类）或纯人声版（采访类）：`render.py` 自动出。
- `out/<片名>-v<N>-卡点表.md`（`cuesheet.py`）。
- `work/qa/<名>.QA.json`、`work/render/<名>.json`。
- `HANDOFF.md`：定版说明、关键参数、用户意见和对应改动、已知例外。

定版后跑 `state.py <proj> approve film --quote "用户原话"`。`out/` 只留最近两版。
